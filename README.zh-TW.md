# DumpingGround

[English](README.md) · [简体中文](README.zh-CN.md) · [日本語](README.ja.md) · [한국어](README.ko.md)

Windows 原生維護工具，Go + [MyGo](https://github.com/egoist/mygo) 原生 UI——
即時硬體總覽、處理程序檢視、磁碟空間分析、啟動項目管理，以及**安全**清理
（Rust 建置產物、Windows 垃圾、附殘留檢閱的完整解除安裝）。以 Task
Manager / Process Explorer / WizTree / Autoruns 的常用工作流程為目標。

## 安全模型

這個應用程式會刪除東西，所以規則先行：

- **預設可逆**。能進資源回收筒的一律進回收筒。Windows 會靜默繞過回收筒的
  情況（單項超過容量、回收筒已停用、磁碟不支援回收）——原地保留並回報錯誤，
  絕不降級成永久刪除。
- **明確確認**。Clean 要點兩次。登錄檔殘留先匯出 `.reg` 備份（UTF-16、
  型別忠實保留），備份沒寫成功就不刪。
- **不靜默擴大範圍**。刪除時複查守衛：執行中的處理程序、重解析點、被其他
  已安裝應用程式佔用的路徑、目前的 Rust 工具鏈、進行中的 Windows 服務。
- **理由可見**。每條殘留都顯示路徑和判定原因；猜測項目一律不預選。
- **開關而非刪除**。關掉啟動項目從不移除它的條目；Windows 內建的服務與
  工作只讀。

## 執行

從 Releases 下載 `DumpingGround.exe`，或按下方建置。雙擊後在 UAC 提示中
點「是」——應用程式以系統管理員權限執行，和 WizTree、BCUninstall 一個
模式。再次啟動會聚焦既有視窗。

### 權限

啟動時一次性要求系統管理員——NTFS 日誌、MFT 快速掃描、HKLM 殘留刪除與
系統目錄清理都依賴它，所以開頭問一次，而不是在每個操作中途打斷。狀態列的
`⛨ admin` 徽章顯示目前狀態。

即使已提升權限，應用程式也不啟用 `SeDebugPrivilege`：核心保護的處理程序
（csrss、lsass、防毒軟體）一律碰不到——結束它們會直接藍屏，而讀取 lsass
記憶體正是憑證竊取工具的特徵動作。禁區邊界交給核心畫，是特性不是缺陷。

### 命令列

- `--page=computer|processes|disk|startup`——啟動時開啟的頁面（預設
  `computer`）。
- `--scan=<磁碟機或資料夾>`——開啟磁碟頁並開始掃描。
- `--renderer=cpu|gpu`——軟體繪製（預設）或 D3D11。

### 狀態與記錄

應用程式記住的一切——每次變更的稽核記錄、服務啟動類型的復原紀錄、
解除安裝歷史和未完成的殘留複查——都放在 `DumpingGround.exe` 旁邊的
`.data` 資料夾裡，整個目錄可以直接攜帶：複製到 USB 碟或另一台機器，
狀態跟著走。如果 exe 旁邊的資料夾無法建立或寫入（唯讀媒體、受保護
位置），則退回 `%LOCALAPPDATA%\DumpingGround`。`.data` 首次建立時
會把舊版本留在 `%LOCALAPPDATA%` 的狀態全部遷移過來，不會丟東西。

頁面快速鍵：Ctrl+1 Computer、Ctrl+2 Processes、Ctrl+3 Disk Usage、
Ctrl+4 Uninstall、Ctrl+5 Startup。

### 電腦

啟動後預設開啟的頁面（Ctrl+1；Ctrl+2–5 依序為其他頁籤）。

- 頂部是整機身分：電腦名稱、品牌型號、Windows 版本與組建編號、處理器、
  記憶體、顯示卡、儲存、網路、主機板和 BIOS——資料來自 SMBIOS、登錄檔
  和 DXGI。
- 每個硬體一張即時卡片：CPU、記憶體、每個 GPU、每個磁碟、每個已連接的
  網路介面卡，筆電還有電池。卡片顯示目前數值和捲動 60 秒的即時圖表。
- 點擊卡片進入詳細頁：大圖表、即時指標和完整規格——每個邏輯處理器的
  曲線與快取大小、記憶體模組（插槽、容量、類型、速度、料號）、GPU 各
  引擎與視訊記憶體、磁碟活動時間/輸送量/磁碟區、網卡位址與連結速率。
  按 Back、Esc、Backspace 或滑鼠側鍵返回；再點一次 Computer 頁籤也會
  回到總覽。
- 不安裝任何驅動程式、不寫入任何內容：資料來源是 SMBIOS、
  `NtQuerySystemInformation`、效能計數器（PDH）、磁碟效能 IOCTL 和
  IP Helper API。不顯示溫度和風扇轉速——Windows 只透過廠商驅動程式
  才公開這些。
- SSD 健康度來自硬碟自己的 NVMe SMART/健康日誌（日誌頁 0x02）：溫度、
  已用壽命與可用備用區塊、累計讀寫量、通電時長、通電次數、不安全關機
  次數和媒體錯誤。結論——良好 / 注意 / 需要更換——用的是 NVMe 規範
  自己的判據，並且總會列出依據，不編造「健康分數」。SATA 硬碟則讀
  ATA SMART 屬性（重新配置磁區、待定磁區、無法修正磁區、溫度、通電
  時長，以及硬碟提供的磨損值）。由於這些屬性編號由廠商自訂，只有各
  廠商含義一致的讀數參與判定，其餘按硬碟原樣顯示。兩種都讀不到的硬碟
  （USB 橋接，或走 Intel RST/VMD 的 NVMe）會如實說明，而不是猜。
- 更細的部件資訊：混合架構 CPU 的 P 核/E 核拆分、每個磁碟的序號、
  韌體版本和磁碟分割表類型（GPT/MBR）、網卡的收發錯誤與丟包計數，
  以及電池的設計容量、滿充容量、循環次數和化學類型——電池磨損直接
  讀自電池韌體。
- 其餘硬體的靜態卡片：每個已連接顯示器一張（從 EDID 解出廠商、型號、
  序號、面板尺寸、原生解析度和目前解析度）、音訊介面卡與端點，以及
  所有在線的隨插即用裝置（按類別和廠商列出）。已拔除的顯示器在登錄檔
  裡留下的舊 EDID 會被過濾掉。

### 處理程序

- 預設平鋪全部處理程序，勾選 Tree 切換父子樹；處理程序數始終顯示在頂部。
- 搜尋名稱、PID 或路徑；點擊欄位標題排序。
- CPU、工作集、私人認可量、讀寫速率和執行緒數；無法存取的處理程序顯示
  不可用狀態。
- Pause 暫停取樣，重新整理間隔可選 1/2/5 秒，F5 手動重新整理。
- 選中處理程序後 Details 或右鍵 Properties：檢視命令列、使用者、提升
  狀態、控制代碼數、模組清單和執行緒清單。
- 開啟檔案位置、複製路徑；結束處理程序/處理程序樹先在應用程式內確認，
  並核對建立時間以防 PID 被重用。

### 磁碟

1. 下拉選擇磁碟機並點 Scan drive；也可以點磁碟機卡片上的掃描按鈕。
2. Browse… 選擇目錄，或在路徑框輸入目錄後點 Scan。
3. 掃描時顯示即時計數；Cancel 保留已收集的部分結果。
4. 結果上半部分是目錄樹/檔案表與副檔名統計，下半部分是空間圖，
   分隔條可拖動。
5. Enter/雙擊向下鑽取，Up/Root 返回；點擊空間圖檔案定位到表中。
6. Allocated / Logical 切換口徑；Export CSV 匯出；Clear index 清除
   記憶體索引。

整碟 NTFS 掃描會嘗試唯讀 MFT 路徑，失敗退回目錄遍歷並顯示原因。嚴格
對照驗證使用獨立的 `DumpingGround-verify.exe`，失敗標 `INCONCLUSIVE`，
不冒充通過。

### 清理

- Rust 建置產物（預設分檔：target 目錄、cargo 快取；目前工具鏈和
  settings/overrides 引用的專案受保護）。
- Windows 垃圾（暫存檔案、快取、可選 Downloads），帶齡期和佔用檢查；
  瀏覽器執行時跳過其快取。
- 資源回收筒本身永遠不在任何預設裡。

### 解除安裝

- 啟動軟體自帶的解除安裝程式（需要時提升權限），然後盯登錄檔條目——
  條目真消失才彈出殘留檢閱，中途取消解除安裝 = 什麼都沒發生。
- 殘留掃描涵蓋檔案、啟動項目、登錄檔機碼；每條標 Confirmed（有證據）或
  Likely（名稱匹配，從不預選）。
- 登錄檔刪除先備份；檔案一律走資源回收筒。

### 啟動項目

所有會自動啟動的東西，一張清單，每項一個開關：

- **應用程式**——`Run` 登錄檔機碼（目前使用者、所有使用者、32 位元）
  和兩個啟動資料夾。
- **服務**——自動和延遲自動啟動的服務，以及已被關掉的。
- **排定工作**——在登入或開機時觸發的工作。

每列顯示發行者（取自程式自帶的版本資訊）、此刻是否在執行、完整命令。
選中一列會說明它設定在哪、開關會產生什麼效果。

不刪除任何東西，每個開關都能復原：

- 應用程式用 `StartupApproved` 旗標——Task Manager 用的同一機制——
  `Run` 值或捷徑原地不動。
- 排定工作透過工作排程器本身啟用/停用。
- 服務改啟動類型；原值（自動、是否延遲）會被記住，開啟開關時原樣復原。
  關服務前會先確認；正在執行的服務會一直執行到下次開機。
- Windows 內建的服務和工作預設隱藏，顯示時唯讀，按「誰做的程式」判定
  而不是看路徑——`System32\DriverStore` 下的廠商驅動服務仍可操作。
- 每次變更都寫進應用程式記錄。

## 建置

Go 1.27+，MyGo 固定 v0.3.5。無需 Bun、WebView2 或 C 工具鏈。

```powershell
go test ./...
$env:CGO_ENABLED = "0"
go build -tags mygo_noinspector -trimpath -ldflags "-s -w -H=windowsgui" -o build/DumpingGround.exe ./cmd/dumpingground
```

預設 CPU 繪製；`--renderer=gpu` 切換 D3D11。
