# DumpingGround

[English](README.md) · [简体中文](README.zh-CN.md) · [繁體中文](README.zh-TW.md) · [한국어](README.ko.md)

Windows ネイティブのメンテナンスユーティリティ。Go + [MyGo](https://github.com/egoist/mygo)
ネイティブ UI で、ライブのハードウェア概要、プロセス監視、ディスク使用量
分析、スタートアップ管理、そして**安全な**クリーンアップ（Rust ビルド
成果物、Windows のジャンク、残留物レビュー付きの完全アンインストール）
を提供します。Task Manager / Process Explorer / WizTree / Autoruns の
日常的なワークフローを目指しています。

## 安全性モデル

このアプリはファイルを削除するので、まずルールから：

- **既定では可逆**。ごみ箱に入れられるものはすべてごみ箱へ。Windows が
  ごみ箱を黙ってバイパスする場合（容量超過、ごみ箱無効、リサイクル非対応の
  ドライブ）は、その場に残してエラーを報告します。完全削除に格下げすることは
  絶対にありません。
- **明示的な確認**。Clean は二度クリックが必要です。レジストリの残留物は
  削除前に `.reg` バックアップ（UTF-16、型を保持）へエクスポートし、
  有効なバックアップがなければ削除しません。
- **暗黙の拡大なし**。削除時にガードを再チェック：実行中のプロセス、
  リパースポイント、他のインストール済みアプリが使用中のパス、現行の
  Rust ツールチェーン、進行中の Windows サービシング。
- **理由の可視化**。すべての残留物にパスとフラグの理由を表示します。
  推測の項目は事前選択されません。
- **削除ではなくスイッチ**。スタートアップ項目をオフにしてもエントリは
  消えません。Windows 標準のサービスとタスクは読み取り専用です。

## 実行

Releases から `DumpingGround.exe` をダウンロードするか、下記の手順で
ビルドしてください。ダブルクリック後、UAC プロンプトで「はい」を選択——
WizTree や BCUninstall と同様、アプリは管理者権限で実行されます。
再起動すると既存のウィンドウにフォーカスします。

### 権限

起動時に一度だけ管理者権限が必要です——NTFS ジャーナル、MFT スキャン、
HKLM 残留物の削除、システムディレクトリのクリーンアップがすべてこれに
依存するため、後の操作のたびに中断するのではなく最初にまとめて要求します。
ステータスバーの `⛨ admin` バッジが現在の状態を示します。

管理者権限であっても `SeDebugPrivilege` は有効にしません：カーネル保護
プロセス（csrss、lsass、ウイルス対策ソフト）は手の届かない場所にあり
ます——これらを強制終了するとブルースクリーンになり、lsass のメモリ
読み取りは資格情報窃取ツールの特徴的な動作です。カーネルが引く境界線は
制限ではなく機能です。

### コマンドライン

- `--page=computer|processes|disk|startup` — 起動時に開くページ
  （既定は `computer`）。
- `--scan=<ドライブまたはフォルダ>` — ディスクページを開いてスキャン開始。
- `--renderer=cpu|gpu` — ソフトウェアレンダリング（既定）または D3D11。

### 状態とログ

アプリが記憶するすべて——すべての変更の監査ログ、サービス開始種別の
元に戻す記録、アンインストール履歴、未完了の残留物レビュー——は
`DumpingGround.exe` の隣の `.data` フォルダに保存されます。フォルダ
ごとポータブルです：USB メモリや別のマシンにコピーすれば、状態も一緒に
移動します。exe の隣にフォルダを作成・書き込みできない場合（読み取り
専用メディア、保護された場所）は `%LOCALAPPDATA%\DumpingGround` に
フォールバックします。`.data` の初回作成時には、以前のバージョンが
`%LOCALAPPDATA%` に残した状態をすべて引き継ぐため、何も失われません。

ページショートカット：Ctrl+1 Computer、Ctrl+2 Processes、Ctrl+3 Disk
Usage、Ctrl+4 Uninstall、Ctrl+5 Startup。

### Computer

アプリ起動時に開くページです（Ctrl+1。Ctrl+2–5 は他のタブ）。

- 上部はマシンの識別情報：コンピュータ名、メーカーとモデル、Windows
  エディションとビルド、プロセッサ、メモリ、グラフィックス、ストレージ、
  ネットワーク、マザーボード、BIOS——SMBIOS、レジストリ、DXGI から
  取得します。
- ハードウェアごとにライブカード：CPU、メモリ、各 GPU、各ディスク、
  接続中のネットワークアダプター、ノート PC ではバッテリー。各カードに
  現在値と 60 秒間のローリンググラフを表示します。
- カードをクリックすると詳細ページへ：大きなグラフ、ライブ数値、完全な
  仕様——論理プロセッサごとのグラフとキャッシュサイズ、メモリモジュール
  （スロット、容量、種類、速度、型番）、GPU エンジンと VRAM、ディスクの
  アクティブ時間/スループット/ボリューム、アダプターのアドレスとリンク
  速度。Back、Esc、Backspace、またはマウスの戻るボタンで戻ります。
  Computer タブを再度クリックしても概要に戻ります。
- ドライバーは一切インストールせず、書き込みもしません：データソースは
  SMBIOS、`NtQuerySystemInformation`、パフォーマンスカウンター（PDH）、
  ディスクパフォーマンス IOCTL、IP Helper API です。温度とファン回転数は
  表示しません——Windows はベンダードライバー経由でしか公開しません。
- SSD の健康状態はドライブ自身の NVMe SMART/Health ログ（ログページ
  0x02）から取得：温度、使用済み寿命と利用可能な予備ブロック、累計
  読み書き量、通電時間、電源投入回数、不安全なシャットダウン回数、
  メディアエラー。判定——Good / Caution / Replace——は NVMe 仕様
  そのものの基準を使い、常に根拠を表示します。捏造された「健康スコア」は
  ありません。SATA ドライブは ATA SMART 属性を読み取ります（代替済み・
  保留中・訂正不能セクター、温度、通電時間、ドライブが提供する摩耗値）。
  これらの属性番号はベンダー定義のため、すべてのベンダーで意味が同じ
  読み取り値のみが判定に使われ、残りはドライブの報告どおりに表示します。
  どちらも応答しないドライブ（USB ブリッジ、Intel RST/VMD 経由の NVMe）
  は、推測せずにその旨を明示します。
- 各部品の詳細情報：ハイブリッド CPU の P コア/E コア内訳、各ディスクの
  シリアル番号、ファームウェアリビジョン、パーティションテーブル
  （GPT/MBR）、ネットワークアダプターのエラー・ドロップパケットカウンター、
  バッテリーの設計容量と満充電容量、サイクル数、化学組成——バッテリーの
  摩耗はバッテリーファームウェアから直接読み取ります。
- その他のハードウェアの静的カード：接続中のモニターごとに 1 枚（EDID
  からメーカー、モデル、シリアル、パネルサイズ、ネイティブ解像度と現在の
  解像度をデコード）、オーディオアダプターとエンドポイント、すべての
  オンライン Plug-and-Play デバイス（クラスとベンダー別）。取り外された
  モニターがレジストリに残した古い EDID は除外されます。

### Processes

- 既定は全プロセスのフラットリスト。Tree チェックボックスで親子ツリー表示に
  切り替え。プロセス数は常に上部に表示。
- 名前、PID、パスで検索。ヘッダーをクリックしてソート。
- CPU、ワーキングセット、プライベートコミット、I/O レート、スレッド数。
  アクセスできないプロセスは利用不可として表示。
- Pause でサンプリング停止、間隔は 1/2/5 秒から選択、F5 で手動更新。
- プロセス選択後に Details または右クリック Properties：コマンドライン、
  ユーザー、昇格状態、ハンドル数、モジュール一覧、スレッド一覧。
- ファイルの場所を開く、パスをコピー。プロセス/プロセスツリーの終了は
  アプリ内で確認し、PID の再利用に備えて作成時刻を照合します。

### Disk usage

1. ドライブを選択して Scan drive、またはドライブカードのスキャンボタン。
2. Browse… でディレクトリを選択、またはパスを入力して Scan。
3. スキャン中はライブカウンターを表示。Cancel は部分的な結果を保持。
4. 結果の上半分はディレクトリツリー/ファイルテーブルと拡張子統計、
   下半分は領域マップ。分割バーはドラッグ可能。
5. Enter/ダブルクリックでドリルダウン、Up/Root で戻る。マップ上のファイルを
   クリックするとテーブル内で特定。
6. Allocated / Logical の切り替え、Export CSV、Clear index でインデックス解放。

ドライブ全体の NTFS スキャンは読み取り専用の MFT パスを試み、失敗時は
理由を表示して通常の走査にフォールバックします。厳密な検証には別の
`DumpingGround-verify.exe` を使い、合格を装わず `INCONCLUSIVE` を
報告します。

### Cleanup

- Rust ビルド成果物（プリセット別：target ディレクトリ、cargo キャッシュ。
  現行ツールチェーンと settings/overrides で参照されるプロジェクトは保護）。
- Windows ジャンク（一時ファイル、キャッシュ、オプションの Downloads）。
  経過時間と使用中チェック付き。ブラウザー実行中はそのキャッシュをスキップ。
- ごみ箱自体はどのプリセットにも含まれません。

### Uninstall

- アプリ自身のアンインストーラーを起動し（必要に応じて昇格）、レジストリ
  エントリを監視——エントリが本当に消えたときだけ残留物レビューが開きます。
  途中でキャンセル = 何も起きません。
- 残留物スキャンはファイル、スタートアップエントリ、レジストリキーを網羅。
  各項目は Confirmed（証拠あり）または Likely（名前一致、事前選択なし）。
- レジストリの削除は事前にバックアップ。ファイルはすべてごみ箱へ。

### Startup

自動起動するすべてのものを、スイッチ付きの 1 つのリストに：

- **アプリ**——`Run` キー（現在のユーザー、全ユーザー、32 ビット）と
  2 つのスタートアップフォルダ。
- **サービス**——自動および遅延自動開始のサービス、無効化済みのもの。
- **スケジュールされたタスク**——サインインまたは起動時に発火するタスク。

各行には発行元（プログラム自身のバージョンリソースから）、現在実行中か
どうか、完全なコマンドが表示されます。行を選択すると、どこに設定されて
いて、スイッチが何をするかが説明されます。

何も削除せず、すべてのスイッチは元に戻せます：

- アプリは `StartupApproved` フラグを使用——Task Manager と同じ仕組み——
  `Run` 値やショートカットはそのまま残ります。
- タスクはタスクスケジューラーを通じて有効/無効化。
- サービスは開始種別を変更。元の値（自動、遅延かどうか）を記憶し、
  オンに戻すときに復元します。サービスをオフにする前に確認し、実行中の
  サービスは次の起動まで動き続けます。
- Windows 標準のサービスとタスクは既定で非表示、表示時は読み取り専用。
  パスではなく「誰が作ったプログラムか」で判定——`System32\DriverStore`
  配下のベンダードライバーサービスは操作可能です。
- すべての変更はアプリログに記録されます。

## ビルド

Go 1.27+、MyGo は v0.3.5 に固定。Bun、WebView2、C ツールチェーンは不要。

```powershell
go test ./...
$env:CGO_ENABLED = "0"
go build -tags mygo_noinspector -trimpath -ldflags "-s -w -H=windowsgui" -o build/DumpingGround.exe ./cmd/dumpingground
```

既定は CPU レンダリング。`--renderer=gpu` で D3D11 に切り替え。
