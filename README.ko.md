# DumpingGround

[English](README.md) · [简体中文](README.zh-CN.md) · [繁體中文](README.zh-TW.md) · [日本語](README.ja.md)

Go + [MyGo](https://github.com/egoist/mygo) 네이티브 UI로 만든 Windows
네이티브 유지 관리 유틸리티——실시간 하드웨어 개요, 프로세스 검사, 디스크
사용량 분석, 시작 프로그램 관리, 그리고 **안전한** 정리(Rust 빌드 아티팩트,
Windows 정크, 잔여물 검토가 포함된 완전 제거)를 제공합니다. Task Manager /
Process Explorer / WizTree / Autoruns의 일상적인 워크플로를 목표로 합니다.

## 안전 모델

이 앱은 파일을 삭제하므로 규칙이 먼저입니다:

- **기본적으로 되돌릴 수 있음**. 휴지통에 넣을 수 있는 것은 모두 휴지통으로
  보냅니다. Windows가 휴지통을 조용히 우회하는 경우(용량 초과 항목, 휴지통
  비활성화, 재활용을 지원하지 않는 드라이브)에는 항목을 그 자리에 두고
  오류를 보고합니다——영구 삭제로 격하하지 않습니다.
- **명시적 확인**. Clean은 두 번 클릭해야 합니다. 레지스트리 잔여물은
  제거하기 전에 `.reg` 백업(UTF-16, 형식 보존)으로 내보내며, 유효한 백업이
  없으면 삭제하지 않습니다.
- **조용한 범위 확장 없음**. 삭제 시점에 가드를 다시 확인합니다: 실행 중인
  프로세스, 재분석 지점, 다른 설치된 앱이 점유한 경로, 현재 Rust 툴체인,
  진행 중인 Windows 서비싱.
- **이유가 보임**. 모든 잔여물은 경로와 플래그된 이유를 표시합니다.
  추측성 항목은 미리 선택되지 않습니다.
- **삭제가 아닌 스위치**. 시작 항목을 꺼도 해당 항목은 제거되지 않습니다.
  Windows 기본 서비스와 작업은 읽기 전용입니다.

## 실행

Releases에서 `DumpingGround.exe`를 다운로드하거나 아래 방법으로 빌드하세요.
더블클릭 후 UAC 프롬프트에서 "예"를 선택하면——WizTree나 BCUninstall처럼
관리자 권한으로 실행됩니다. 다시 실행하면 기존 창이 활성화됩니다.

### 권한

시작 시 한 번 관리자 권한이 필요합니다——NTFS 저널, MFT 스캔, HKLM 잔여물
삭제, 시스템 디렉터리 정리가 모두 여기에 의존하므로 이후 작업마다 중단하지
않고 처음에 한 번만 요청합니다. 상태 표시줄의 `⛨ admin` 배지가 현재 상태를
보여줍니다.

권한이 상승된 상태에서도 앱은 `SeDebugPrivilege`를 활성화하지 않습니다:
커널이 보호하는 프로세스(csrss, lsass, 백신)에는 닿을 수 없습니다——
이를 강제 종료하면 블루스크린이 발생하고, lsass 메모리 읽기는 자격 증명
탈취 도구의 전형적인 동작입니다. 커널이 긋는 경계선은 제한이 아니라
기능입니다.

### 명령줄

- `--page=computer|processes|disk|startup` — 시작 시 열 페이지
  (기본값 `computer`).
- `--scan=<드라이브 또는 폴더>` — 디스크 페이지를 열고 스캔을 시작합니다.
- `--renderer=cpu|gpu` — 소프트웨어 렌더링(기본값) 또는 D3D11.

### 상태와 로그

앱이 기억하는 모든 것——모든 변경의 감사 로그, 서비스 시작 유형 되돌리기
기록, 제거 기록, 보류 중인 잔여물 검토——은 `DumpingGround.exe` 옆의
`.data` 폴더에 저장됩니다. 폴더 전체가 포터블입니다: USB 스틱이나 다른
머신에 복사하면 상태도 함께 이동합니다. exe 옆에 폴더를 만들거나 쓸 수
없는 경우(읽기 전용 미디어, 보호된 위치)에는 `%LOCALAPPDATA%\DumpingGround`로
대체됩니다. `.data`가 처음 만들어질 때 이전 버전이 `%LOCALAPPDATA%`에
남긴 상태를 모두 가져오므로 아무것도 버려지지 않습니다.

페이지 단축키: Ctrl+1 Computer, Ctrl+2 Processes, Ctrl+3 Disk Usage,
Ctrl+4 Uninstall, Ctrl+5 Startup.

### Computer

앱이 시작될 때 열리는 페이지입니다(Ctrl+1. Ctrl+2–5는 다른 탭).

- 상단에는 머신의 ID 정보: 컴퓨터 이름, 제조사와 모델, Windows 에디션과
  빌드, 프로세서, 메모리, 그래픽, 스토리지, 네트워크, 마더보드, BIOS——
  SMBIOS, 레지스트리, DXGI에서 읽어옵니다.
- 하드웨어마다 라이브 카드 하나씩: CPU, 메모리, 각 GPU, 각 디스크, 연결된
  각 네트워크 어댑터, 노트북에서는 배터리. 현재 값과 60초 롤링 차트를
  표시합니다.
- 카드를 클릭하면 상세 페이지로: 큰 차트, 실시간 수치, 전체 사양——논리
  프로세서별 차트와 캐시 크기, 메모리 모듈(슬롯, 용량, 유형, 속도, 부품
  번호), GPU 엔진과 VRAM, 디스크 활성 시간/처리량/볼륨, 어댑터 주소와
  링크 속도. Back, Esc, Backspace 또는 마우스 뒤로 버튼으로 돌아갑니다.
  Computer 탭을 다시 클릭해도 개요로 돌아갑니다.
- 드라이버를 설치하지 않고 아무것도 쓰지 않습니다: 데이터 소스는 SMBIOS,
  `NtQuerySystemInformation`, 성능 카운터(PDH), 디스크 성능 IOCTL,
  IP Helper API입니다. 온도와 팬 속도는 표시하지 않습니다——Windows는
  벤더 드라이버를 통해서만 이를 노출합니다.
- SSD 상태는 드라이브 자체의 NVMe SMART/Health 로그(로그 페이지 0x02)에서
  가져옵니다: 온도, 사용된 수명과 사용 가능한 예비 블록, 누적 읽기/쓰기량,
  전원 켜짐 시간, 전원 사이클 수, 안전하지 않은 종료 횟수, 미디어 오류.
  판정——양호 / 주의 / 교체 필요——은 NVMe 사양 자체의 기준을 사용하며
  항상 근거를 보여줍니다. 지어낸 "건강 점수"는 없습니다. SATA 드라이브는
  ATA SMART 속성을 읽습니다(재할당·보류·교정 불가 섹터, 온도, 전원 켜짐
  시간, 드라이브가 제공하는 마모 값). 이 속성 번호는 벤더 정의이므로 모든
  벤더에서 의미가 동일한 값만 판정에 사용하고 나머지는 드라이브가 보고한
  그대로 보여줍니다. 둘 다 응답하지 않는 드라이브(USB 브리지, Intel
  RST/VMD 뒤의 NVMe)는 추측 대신 그 사실을 알려줍니다.
- 각 부품이 보고하는 더 자세한 정보: 하이브리드 CPU의 P코어/E코어 분할,
  각 디스크의 일련번호, 펌웨어 리비전, 파티션 테이블(GPT/MBR), 네트워크
  어댑터의 오류·드롭 패킷 카운터, 배터리의 설계 용량 대 완충 용량, 사이클
  수, 화학 조성——배터리 마모는 배터리 펌웨어에서 직접 읽습니다.
- 나머지 하드웨어의 정적 카드: 연결된 모니터마다 하나씩(EDID에서 제조사,
  모델, 일련번호, 패널 크기, 기본 해상도와 현재 해상도를 디코딩), 오디오
  어댑터와 엔드포인트, 온라인 상태의 모든 플러그 앤 플레이 장치(클래스와
  벤더별). 분리된 모니터가 레지스트리에 남긴 오래된 EDID는 걸러냅니다.

### Processes

- 기본은 전체 프로세스의 플랫 목록. Tree 확인란으로 부모/자식 트리 전환.
  프로세스 수는 항상 상단에 표시.
- 이름, PID, 경로로 검색. 헤더를 클릭해 정렬.
- CPU, 워킹 세트, 프라이빗 커밋, I/O 속도, 스레드 수. 접근할 수 없는
  프로세스는 사용 불가로 표시.
- Pause로 샘플링 일시 중지, 간격은 1/2/5초 선택, F5로 수동 새로 고침.
- 프로세스를 선택한 뒤 Details 또는 우클릭 Properties: 명령줄, 사용자,
  권한 상승 상태, 핸들 수, 모듈 목록, 스레드 목록.
- 파일 위치 열기, 경로 복사. 프로세스/프로세스 트리 종료는 앱 내에서 확인하고
  PID 재사용에 대비해 생성 시간을 대조합니다.

### Disk usage

1. 드라이브를 선택하고 Scan drive를 누르거나, 드라이브 카드의 스캔 버튼 사용.
2. Browse…로 디렉터리를 선택하거나 경로를 입력한 뒤 Scan.
3. 스캔 중 실시간 카운터 표시. Cancel은 부분 결과를 유지.
4. 결과 상단은 디렉터리 트리/파일 테이블과 확장자 통계, 하단은 공간 맵.
   분할 막대는 드래그 가능.
5. Enter/더블클릭으로 드릴다운, Up/Root로 돌아가기. 맵의 파일을 클릭하면
   테이블에서 위치를 찾습니다.
6. Allocated / Logical 전환. Export CSV. Clear index로 인덱스 해제.

드라이브 전체 NTFS 스캔은 읽기 전용 MFT 경로를 시도하고, 실패하면 이유를
표시하며 일반 순회로 대체합니다. 엄격한 검증은 별도의
`DumpingGround-verify.exe`를 사용하며 통과한 척하지 않고 `INCONCLUSIVE`를
보고합니다.

### Cleanup

- Rust 빌드 아티팩트(프리셋별: target 디렉터리, cargo 캐시. 현재 툴체인과
  settings/overrides에서 참조되는 프로젝트는 보호됨).
- Windows 정크(임시 파일, 캐시, 요청 시 Downloads). 경과 시간과 사용 중
  검사 포함. 브라우저 실행 중에는 해당 캐시를 건너뜀.
- 휴지통 자체는 어떤 프리셋에도 포함되지 않습니다.

### Uninstall

- 앱 자체의 제거 프로그램을 실행하고(필요 시 권한 상승) 레지스트리 항목을
  감시합니다——항목이 실제로 사라졌을 때만 잔여물 검토가 열립니다. 중간에
  취소하면 아무 일도 일어나지 않습니다.
- 잔여물 스캔은 파일, 시작 항목, 레지스트리 키를 다룹니다. 각 항목은
  Confirmed(증거 있음) 또는 Likely(이름 일치, 미리 선택되지 않음)로
  표시됩니다.
- 레지스트리 삭제는 먼저 백업. 파일은 모두 휴지통으로 갑니다.

### Startup

자동으로 시작되는 모든 것을 스위치가 달린 하나의 목록으로:

- **앱**——`Run` 키(현재 사용자, 모든 사용자, 32비트)와 두 개의 시작
  프로그램 폴더.
- **서비스**——자동 및 지연된 자동 시작 서비스, 그리고 꺼진 것들.
- **예약된 작업**——로그인 또는 부팅 시 실행되는 작업.

각 행에는 게시자(프로그램 자체의 버전 리소스에서), 지금 실행 중인지 여부,
전체 명령이 표시됩니다. 행을 선택하면 어디에 구성되어 있는지, 스위치가
무엇을 하는지 설명합니다.

아무것도 삭제하지 않으며 모든 스위치는 되돌릴 수 있습니다:

- 앱은 `StartupApproved` 플래그 사용——Task Manager가 쓰는 것과 같은
  메커니즘——`Run` 값이나 바로 가기는 그 자리에 그대로 남습니다.
- 작업은 작업 스케줄러 자체를 통해 활성화/비활성화.
- 서비스는 시작 유형을 변경. 원래 값(자동, 지연 여부)을 기억하고 다시 켤 때
  복원합니다. 서비스를 끄기 전에 확인하며, 실행 중인 서비스는 다음 부팅까지
  계속 실행됩니다.
- Windows 기본 서비스와 작업은 기본적으로 숨겨져 있고 표시되어도 읽기 전용.
  경로가 아니라 "누가 만든 프로그램인가"로 판단——`System32\DriverStore`
  아래의 벤더 드라이버 서비스는 여전히 전환 가능합니다.
- 모든 변경은 앱 로그에 기록됩니다.

## 빌드

Go 1.27+, MyGo는 v0.3.5로 고정. Bun, WebView2, C 툴체인 불필요.

```powershell
go test ./...
$env:CGO_ENABLED = "0"
go build -tags mygo_noinspector -trimpath -ldflags "-s -w -H=windowsgui" -o build/DumpingGround.exe ./cmd/dumpingground
```

기본은 CPU 렌더링. `--renderer=gpu`로 D3D11 전환.
